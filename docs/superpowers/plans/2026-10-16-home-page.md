# a6n.ai Home Page (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the cyanotype site with the new Home page: a Creation of Adam hero with "Book a call", a "Who we help" band, one colored Anatomy machine (the Foundry workbench), and a closing CTA, deployed to a6n.ai.

**Architecture:** This is static Astro. The Anatomy kit is vendored into `src/lib/anatomy/` and runs **at build time** in Astro frontmatter, emitting SVG strings, so the machine renders with zero JS. A small client module steps the machine's story. WebGL (hero light) loads after first paint as a progressive layer over the painting. A Node check script asserts content rules against `dist/`.

**Tech Stack:** Astro 7, TypeScript, `astro:assets`, Astro fonts API, Anatomy kit (`~/.claude/skills/anatomy/kit`, MIT), and `gsap` only for page reveals (already installed). No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-a6n-site-revamp-design.md`

## Global Constraints

- Brand is **a6n**. Never say "Aether" in visible copy.
- Banned words in visible copy and aria-labels (case-insensitive): `API, LLM, agentic, platform, SaaS, stack, integration, backend, webhook, AI-powered, Realm`.
- Only *Live* catalog features are mentioned.
- CTA: `mailto:hi@a6n.ai?subject=Book%20a%20call&body=` + an encoded body asking "What does your business do?" and "When is a good time to talk?".
- Tokens: page `#f2f2ef`, card `#fbfbfa`, strong `#18181a`, text `#57575a`, muted `#8c8c90`, faint `#d4d4d6`, sanguine `#b5523b`, and the Foundry pigment raw umber `#7a5c3e`. All colors are CSS custom properties, with no literals in components.
- Fonts: EB Garamond (display), Inter (body), `ui-monospace` (plate labels), self-hosted, `font-display: swap`.
- Light theme only. Set `color-scheme: light` on `:root`.
- Motion: one entrance per view, no scroll-jacking, and a full still state under `prefers-reduced-motion: reduce`.
- Keep `src/components/Mark.astro` unchanged.
- Gate: `npm run build` passes, `npm run check:site` passes, Lighthouse mobile Performance ≥ 90 and Accessibility ≥ 90, no console errors.

## Review Focus

1. **No JS / WebGL unavailable**: the hero painting, headline, CTA and full machine (final state) must render. Covered by the Task 6 check (machine SVG present in static HTML).
2. **320px-wide phone**: no horizontal scroll, CTA tappable (≥ 44px), and the hands crop doesn't hide the headline. Covered by the Task 6 manual step at 320×640.
3. **Reduced motion**: machine shows the final step with all parts lit, and no shader runs. Covered by the Task 4 and Task 5 guards and the Task 6 manual check.
4. **Dark OS setting**: the page stays light and readable. Covered by the `color-scheme` assertion in Task 6.
5. **Slow connection**: hero image ≤ 180 KB at 800w AVIF, and the shader script isn't render-blocking. Covered by the Task 2 size check and Lighthouse.

### Task 4: The Foundry workbench machine

Invoke the **anatomy** skill for this task (`~/.claude/skills/anatomy/SKILL.md`, `references/craft.md`, `references/motion.md`). Start from `examples/desk-computer` and `examples/test-rig` (spec, Diagram sourcing: adapt).

**Story (fixed, from spec):** "Your new app is built from parts that already work, not from zero." Four steps, each lighting in turn:

| Step | What moves | Label (exact) |
|---|---|---|
| 1 | Drawer of ready parts on the bench: a key (sign-in), a coin (payments), a star token (loyalty), a small van (delivery), an envelope (messages) | `parts that already work` |
| 2 | Two or three parts lift out of the drawer | `pick what you need` |
| 3 | Parts slide into a shop-front frame standing on the bench | `fitted to your business` |
| 4 | The shop-front's window lights (sanguine lit part), and a tiny phone beside it shows the same | `your app, open for customers` |

Caption under the plate (exact): `We don't start from a blank page. Your app is put together from parts already running for other businesses, then shaped around yours.`

Plate corner text (mono): top-left `PLATE II`, top-right `THE WORKSHOP`, bottom-right a step readout `1 / 4`.

**Files:**
- Create: `src/machines/workbench/geometry.ts`, `src/machines/workbench/Workbench.astro`, `src/machines/workbench/live.ts`, `src/machines/workbench/workbench.css`
- Modify: `scripts/check-site.ts`

**Interfaces:**
- Consumes: `src/lib/anatomy/iso-kit.ts`, `anatomy.css`, `--umber`, `--sanguine`.
- Produces: `geometry.ts` exports `export function buildWorkbench(width: number, height: number): { svg: string; steps: 4 }`, a pure function returning the full figure SVG. Every part group carries `data-step="1|2|3|4"`, and moving groups carry `data-move` with their step-start transform. Labels sit **outside** the drawing in the plate margin (Anatomy rule) as HTML `<li data-step>` elements, not SVG text. `Workbench.astro` renders `<figure class="iso-plate" data-machine="workbench">` with the SVG via `set:html`, the four labels as an `<ol>`, prev/next buttons (`aria-label="Previous step"` / `"Next step"`), and the caption as `<figcaption>`. The SVG root has `role="img"` and an `aria-label` that tells all four steps in one sentence. `live.ts` exports `export function mountWorkbench(root: HTMLElement): () => void` (returns cleanup).
- Scope note: the spec's Foundry "forge glow" shader is deferred to Phase 4 polish. The workbench story has no forge, and Phase 1 ships one shader (the hero).
- Colors: all solids use raw umber shaded via `color-mix(in oklab, var(--umber) N%, var(--card))` across Anatomy's four tones. The lit window is sanguine. No other hues.
